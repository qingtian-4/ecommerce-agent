# 家电模拟咨询与主线离线对照

2026-10-28，基于780e9df。用户明确授权启用家电模拟政策咨询，未授权新的付费实验。

## 启用范围

独立数据版本`shop-realism-v1.3`保留v1.2的64商品、304订单、8身份，业务、SKU、物流JSON
逐字节相同。知识文档增至57份，家电模拟政策可检索，旧版本及草案仍保留。

模拟无理由期限7天、质量问题期限15天、整机保修12个月，起算参考签收日，需核验本人订单、
签收事实、购买凭证和商品状况。月末边界、部件差异、特殊情况仍未定义，不能自动判定资格。
用户说“用了两个月”不是已核验签收日期，也不能自动绑定到最近一笔订单。

咨询来源有独立JSON、版本和正文哈希。`consultation=true`与办理用的return/warranty范围
分开；家电仍不能预览、提交申请、退款、安装预约、维修派单或换货。原耳机办理规则、身份
校验、确认和幂等未扩大。页面增加“咨询模拟政策”入口，只预填包含订单/商品的消息，用户
发送后才调用模型；禁用的办理按钮不再误写“暂无适用政策”。免费演示仅转述检索到的原文。

## 本轮主线改动

现有`search_knowledge`增加可选`document_id`。普通查询保持原检索行为；显式指定文档时，
在完整语料的BM25分值上限定来源，再取top-k，未知文档返回空，不回退到耳机政策。
没有新增框架、向量索引、Embedding或Rerank调用，没有改变切分或tokenizer版本。

单独给8个品类相同形式的“模拟保修期限和退货条件”查询：通用检索6/8命中目标政策，漏掉
洗碗机和冰箱；显式来源8/8。单文档重建BM25曾导致负IDF无结果，已改为保留全语料IDF；
失败日志保存。此改善依赖调用者选择来源，不能说模型已能自动选对。

冻结`shop-mainline-v1.1`：8个已见场景、16轮、每臂36个子目标。覆盖家电订单+政策、预算
和否定品类、两实体比较、未知降噪、代词歧义、耳机草稿与家电插问、越权拒绝后继续合法
查询、完整概览与后续规格、聊天确认不能扩权、按商品筛本人订单后跨轮选单。

旧Loop和V3都经过真实SDK序列化、业务SQLite及原Runtime，HTTP为MockTransport。固定用户
输入和脚本决策不由被测模型生成；Gold不进入模型请求。唯一对照差异是知识查询是否指定
来源文档。无新增意图分类器、任务规划器或长期记忆服务。

失败是SX04第一轮：保存耳机草稿后插问家电保修，通用检索未取得家电保修文档。SQL和固定
答案正确也不能补足缺失的证据。指定来源修复该路径，跨轮家电咨询保持原O72001/720010
耳机草稿。36个“SQL相同但漏一个子目标”的反例全部失败；陌生自然语言仍pending_review。
更宽的完整目录、全量本人订单、正确商品文档等合法替代证据也被接受；缺失权限回执不能
通过all([])成为已验证拒绝。最终扩展替代证据后重评分同批原始输出，0个成绩变化。

原v1冻结文件曾遗漏SX05中他人订单/未发货物流的预期拒绝标注，正确拒绝被记作工具失败。

表格使用v1.1同协议对照，没有拿原错误分数制造收益。
