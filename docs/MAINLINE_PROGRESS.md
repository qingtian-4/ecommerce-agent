# 多意图主线进展与当前阻碍

2026-10-28，基于164e596。本轮只读分析既有真实会话，新增付费调用0。

## 这次8/48的真实原因

截图对应真实DeepSeek，不是离线脚本。模型依次取得30笔本人订单和8件目录第一页，
回执明确给出`has_more=true`与续页参数。模型随后主动结束，原答明确写“已展示前8件”，
并询问继续列出还是筛选。账本没有正文超限、费用停止或API失败。后一轮政策咨询的
“通用政策”措辞仍需语义复核，不能把工具检索成功当作答案准确。

页面显示的拒绝文字来自应用保护层：某个目录子查询不完整时，原实现替换了整段回答，
把已返回的订单结果一起遮盖。这是多意图完成状态过粗，不是数据库没有剩余40件商品。

## 本轮落地的最小主线改进

新增`list_products(view="overview")`，完整枚举名称、类别、现价和货币，明确不含规格/
SKU。具体佩戴方式、降噪、颜色、可售状态等条件仍须details或get_product取证。概览超过
16KB时明确失败并提供详细分页入口，不默默截断。32KB实际HTTP上限没有改变。

同一条“订单＋店铺有哪些产品”查询，旧Loop/V3各运行两个脚本路径：已观察到的第一页
路径保留“订单查询已返回30笔”，仅商品部分提示8/48未完成；建议的概览路径一次取得
48/48，最大正文26186字节，两臂相同。此处改变的是工具合同与展示粒度，不是已证明模型
会自主选对工具。没有增加关键词意图分类器，也没有宣称通用任务规划已完成。

冻结了6个开发控制用例，覆盖混合查询、全量概览、已知条件、完整规格、空匹配、概览不能
冒充规格证据。它们是已见问题和作者构造控制，不是未见测试集。原有更长历史压力矩阵仍
保留：新schema使两轮详细扫描正文达到32379字节，仍只剩389字节；概览是按任务需要减少
证据体量，不是解决所有长上下文问题。

## 数据生成收敛为候选工作流

`scripts/generate_demo_candidates.py`读取固定spec、seed与既有业务JSON，产出新的候选
目录和哈希清单。240个订单按ID派生随机种子，使用四条模拟区域路线与不等间隔时间；
出库在运输之前，签收不早于发货，未发货无轨迹，已发货不捏造签收，时间不晚于逻辑快照。
时间带+08:00。相同输入可字节重建，不覆盖旧数据。

截图旧物流重复源于共用一条路线并按等间隔插值；日期处于2026-11，是固定业务时钟
2026-11-06下的演示日期，不是当前真实物流。新生成器仍只提供模拟候选，尚未接入运行
中的数据库，不应称为承运商真实数据。

家电上游资料含安装、维修等说明，但本店当前只导入经过筛选的规格和物流，没有完整的
家电售后合同。候选spec提出7天、15天、12个月作为演示假设，均标为未启用；它们不是法律
或平台标准。`prompts/demo_policy_draft.md`供AI改写受控事实，不能改数字、添加权限或声称
真实平台承诺。当前没有调用AI生成接口，也没有启用家电售后。

固定工作流：结构化事实与版本 → 生成候选（代码负责SQL/时间事实，AI可改写文案） →
外键、金额、日期、适用品类和答案不变性校验 → 业务含义确认 → 新版本冻结 → 离线回归。
参照真实平台政策时必须另记录来源、日期和适用范围，不能将不同平台条款拼成真实合同。
