## C：操作结果与咨询回答分开验证

源码依据是V2.1的`src/acs/write_evidence.py::guarded_answer`：存在写回执时，整段模型回答由
最新scope的summary替换。这保证操作确认有据，但政策、商品说明可能丢失；此前95/444次回复改写
不能视作95次改进。相关源码与记录在`c513061`，不修改旧评分或旧回放文件。

最小方案：先保持现有写回执验证器，新增受限的咨询证据呈现，最后组合两部分。

```text
真实变更回执 ── 现有对象/字段核验 ── 操作结果
只读工具 / KB证据 ── 诉求、对象、来源核对 ── 咨询内容
                                      ↓
                       统一最终回答 → 历史 / Trace / 页面
```

1. 操作结果仍由真实回执及权威状态决定，未知写不重放，预览不能冒充申请或退款。
2. 首轮仅支持已有商品结构化事实、明确政策依据和既有订单事实的混合回答。
   咨询优先由对应只读结果/KB片段及来源生成受限内容，按本轮工具参数与结果对象绑定。
   不直接将原模型余文追加到安全摘要，也不因有引用就认定任意语义正确。
3. 引用政策明确标为规则而非已完成状态；商品事实不能串SKU、订单或颜色。
   无法核验相关性或资料不足时，单独说明咨询部分未完成，不把展示一段材料记成任务完成。
4. 所有用户可见帧均受相同边界约束，最终answer、assistant历史、final Trace及恢复后显示一致。
   用户可见正文不能夹带未经核实的操作完成声明；原答仅作标明用途的诊断证据。
5. 沿用`write_receipt_guard_enabled`消融，新增模型调用为0，不改表结构、API、权限、事务或确认协议。
   最初范围为write_evidence、Loop、既有证据读取和定向测试；UI仅在现有渲染无法表达时最小调整。

不选“继续追加大量关键词”的方向；也不选“咨询正文原样放行，只在旁边加安全卡片”。
后者仍可能让用户看到正文中的虚假完成。若受限证据呈现无法同时通过相关性和完整性验收，
保留旧安全回退并报告未解决，不以删除难题或放宽评分保留代码。
