## 正文流式尚未实现

现有 SSE 是执行进度流：工具请求、工具回执、确认等待和 SQL 核验等。它不是正文 Token 流，不能把“进度已连接”当成逐字回复已经实现。

根因分布在三层：

1. LocalReturnPoc._stream 使用 stream_mode=["updates"]，只导出节点更新。
2. EpisodeSyncTransport/AsyncTransport 沿用 HalfDuplex 预算与取证链路，在获得完整响应与usage后才交给SDK；仅添加 messages 流模式也不能变成真实网络增量输出。
3. 页面在最终 turn_completed 后读取已保存回答，没有正文 delta 事件与恢复契约。

本次没有伪造逐字打字效果。后续真正正文流须同时维护：请求前费用预留、缺失usage的保守记账、响应协议Guard、混合文本/工具调用的语义、敏感字段、最终已核实回答与临时片段区分、断线不重复模型/业务工具，以及历史τ Adapter的HalfDuplex行为。需要独立实施与MockTransport/真实预算验收，不能只开前端开关。
