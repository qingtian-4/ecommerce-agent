# 下一里程碑：隔离业务确认 UI 与 REST/SSE 验收

M6 仅交付本地合成 SQLite 的原子模拟申请与只读恢复；不自动部署，不接真实电商平台，不替换默认 Runtime。进入下一阶段须以最终 CI 和 M6 Scorecard 通过为门禁。

下一轮最小范围：在现有 Python 服务中包装三个受信任应用动作——打开最新预览确认、提交接受/拒绝/取消、查询权威业务回执；将现有聊天 Graph 的消息及等待状态通过受限 REST/SSE 展示。复用当前提交桥和 ReturnService，不再增加业务事务实现。

必须先建立服务端身份/session/CSRF边界，模型和浏览器请求体均不能任意指定用户。应用事件幂等键、preview/revision/policy/expiry绑定由服务端保存；SSE只呈现已有事实，连接断开不等于提交失败，也不能自动再次确认。

| 页面状态 | 判定证据 | 可执行动作 |
|---|---|---|
| 草稿未齐 | 最新业务草稿 | 补信息/更正/取消 |
| 预览可确认 | 最新有效预览 + Graph等待 | 显式接受/拒绝；更正使旧预览失效 |
| 提交处理中或结果未知 | 当前应用事件 + 权威查询 | 查询；不展示成功、不自动重放 |
| 模拟待审核 | 完整 SQL 申请/确认/审计/回执 | 展示申请ID与pending_review，不宣称退款 |
| Graph镜像异常 | SQL回执成功 + 镜像不一致 | 展示已核实业务结果和恢复提示，不重复提交 |
| 失效/越权 | 服务端校验拒绝 | 解释原因，重新预览或正确登录 |

冻结验收：聊天插问与更正、浏览器刷新、重复点击、SSE断线、服务重启、提交前/后退出、迟到/过期/跨用户确认、DB不可用、SQL成功Graph异常。数据库终态与可见事件逐一核对，不能仅检查页面文字或HTTP 200。

Go 限于上述隔离服务/UI接入与评测；生产身份、真实平台权威回执、多Worker协调、备份监控及人工审核流程仍未验收，生产 No-Go。下一轮不要求 React 重写、Redis/PostgreSQL、换货、退款或新模型路由。
