# 电商客服 Agent P1 订单候选事实一致性

本轮按用户最新优先级实施“订单事实一致性”，先处理 orders-01 的候选展示错误。
它对应原架构提案中“先只改订单候选的确定性展示”的窄替代方案；不表示旧提案的
全部对象投影、Context Engineering、事实引用或语义审查已经完成。

## 根因与方案对照

原始 orders-01/trial=1 中，list_orders 返回 S20008/明细 10/V201-2/白色与
S20003/明细 4/V201-1/黑色。模型回答把两笔相同商品名称的订单合并成黑色。
工具没有丢失 SKU，错误发生在自由文本重组阶段；增加检索或事实账本不能直接阻止它。
冻结原始轨迹及来源见 results/p0_order_draft_integrity/acceptance_20261020/next_badcase.json。

| 方案 | 保留能力 | 可靠性边界 | 本轮选择 |
| --- | --- | --- | --- |
| 自由文本重组 | 自由筛选、摘要与追问 | 同一名称下不同订单和 SKU 可被合并；原始错误已复现 | 关闭开关的同条件对照 |
| 按实际工具结果确定性呈现 | 保留每个订单和明细的商品、SKU、颜色、数量、状态及日期 | 只保证表格对应当前工具结果，不保证工具外自由回答、完整资格或跨轮事实 | 独立开关、默认关闭的窄实现 |

不增加审查模型、不修改 Prompt、不改变 list_orders API 或 SQL，不建立 Fact Ledger。
模型仍执行同样两次调用，最终 ChatService 使用确定性表格替换该回合的自由文本；
原自由文本保留在独立事实呈现 Trace 中供诊断，不作为权威结果继续保存到会话消息。
本轮没有减少模型调用，也不能把服务器生成文字计为额外模型输出 Token。

## 最小执行协议

开关：ACS_ORDER_CANDIDATE_RENDER_ENABLED，默认 false；独立于 P0 的开关。
仅满足以下条件时替换最终回答：正常 answered；当前没有任何既有任务且状态可读；
本轮恰好一次 list_orders 调用和成功结果；没有其他工具、工具错误或检索流程。
调用必须先于回执，不从模型回答、历史结果或引用的订单号生成事实。
当前用户由 ChatService 绑定，真实 list_orders 在数据层按用户过滤。

实际工具回执 → 按下单日期降序、订单号升序、明细编号升序排列 → 每条明细独立行
→ 同步 answer、最终 assistant、final Trace → finish_turn 保存。

新增 fact_render 事件记录来源结果索引、绑定的结构化行、当前用户和原始模型答案，
UI 显示为“订单候选事实”，不会显示为模型工具调用或另一个最终回答。
未知 SKU、颜色等显示未知，不从同名商品猜测；Markdown 单元格转义管道、换行、
HTML 和链接/图片语法，避免商品名称改写表格结构或加载外部图片。

空列表明确没有订单。已有 draft、cancelled、submitted 或状态未知时不进入此模式，
混合 get_order、政策检索、草稿更新、异常、超时及多次查询均维持原路径。
P1 不选择订单或商品，不保存草稿、预览或申请，不触发 P0 所需的本人 get_order 证据。

## 覆盖与风险

本轮保守展示实际查询得到的全部订单和商品，不按模型对“最近”“耳机”的理解再做筛选，
也不把发货状态等同于退货资格。完整表格可能比自由摘要长，可能丢失模型原有的筛选、
金额汇总或其他解释；当前仅为纯候选定位回合提供受限呈现，不能视为通用订单回答协议。
正式扩大或默认启用前，需补这些问法的回归与明确路由依据。

不承诺阻止先前已经流出的模型文本。终态会明确显示“候选更正，以本轮查询记录为准”，
保存的回答与消息是权威表格；原错误回复不会混在最终正文里。历史查询、混合工具、
模型主动错写、无工具回答和语义政策判断均不在本轮保证范围内。
直接调用 Agent 的旧评测入口和 τ 适配器不走此 ChatService 挂点，不受本机制保护。

测试使用真实 Loop、ToolRegistry、ChatService、SessionStore 和独立 SQLite，固定假模型。
四组配对为原始错误、SQL 颜色变更、其他用户和本来正确的模型回答；输入与后续轮次固定。
同时验证 25 条明细的绑定、排序、未知、转义、已有草稿、UI 恢复和与 P0 共存时不误补存。
它们均为开发/回归材料，不是独立盲测；真实模型成功率、真实 Token 和费用未测。

运行命令与全部结果见 [本轮报告](../results/p1_order_candidate_facts/REPORT.md)。
关闭开关并重启即可回退，已有会话保留；没有数据库迁移、工具变更或索引重建。
