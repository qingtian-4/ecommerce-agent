# 013612d 二次复审 P2 修复

本轮只修复四项已见 P2，不重跑历史付费实验、不修改冻结标签，不把脚本回归称为盲测或
模型能力结论。旧实现为 013612d，候选验证在排除用户已有修改的独立工作树中进行。

| 问题 | 原因 | 修复与验收 |
|---|---|---|
| 空草稿查询冒充保存完成 | 整句出现“不要”就移除保存动作证据要求 | 按局部请求识别否定；真实 ChatService 必须取得 update_return_task 回执并读回已保存订单 |
| 恢复丢失澄清 | route_hint 仅在本次请求内存中，恢复分支重置为空 | 预约 turn 时同一事务保存保守提示，规划结束后更新；新宿主恢复同 turn，不再调用 planner |
| 国家码号码进入记忆 | 国内号前的数字边界排除了紧邻的 86 | 统一正则识别 +86/0086，包括无空格形式；抽取及 fact/summary/episode 写入均拒绝 |
| 商品量词扩大订单范围 | 从整句提取“所有”并用于 orders goal | 量词仅用于订单分句；指定订单查询加完整商品概览不再要求列全部订单 |

局部证据约束仍是有限措辞规则，不是通用语义解析器，也不扩大写操作权限。路由恢复记录
位于进行中业务 turn 的 `result_json.local_routing`，不是提交成功证据；用户身份、草稿
修改、明确确认、幂等与正式回执仍由已有应用和数据层负责。轮次完成时原终态结果正常保存。
