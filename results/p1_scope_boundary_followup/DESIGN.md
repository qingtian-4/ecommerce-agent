# 电商客服 Agent P1 接管边界实验设计

先冻结、再红测试和局部修复，本轮不 commit/push/merge。固定基线 4b9c3cb，
起始代码 a6cec14（上轮仅修结构安全）。既有 15 段任务及期望不改，新冻结 22 个边界问法。

已确认缺陷：helper 不读用户原话，ChatService 无条件替换纯 list_orders 回答。
上轮主矩阵 11 个有害覆盖仍存在；只增加结构校验不能修好任务相关性。

方案 A：理想化显式全量清单白名单，冻结主矩阵仅三个全量问法允许替换，其他回退。
用实际 Loop 测量它是否丢失原始 orders-01 的颜色修复；不是准备上线的语义路由。

方案 B：完整匹配有限问法，只接管显式无筛选全量明细、全量退货候选、明确耳机退货
候选澄清；其余直接保留模型原答。耳机类别来自 get_order 已经 JOIN 的 product_category，
开关开启时在 list_orders 顶层透传 product_categories（按 product_id 绑定的紧凑映射），
不新增 SQL 或工具。关时 payload 完全不变。该映射是当前工具回执的类别元数据，不持久化。
缺失/未知类别不接管类别模式；不能用商品名推断。最近未有时间边界时仅列全部耳机候选
并明确追问时间范围，不称为已过滤最近时间，不选订单/明细，不办理售后。

不实现通用筛选/计数路由；类别/颜色/状态筛选、统计和短答继续由原 Loop 回答，
本轮只避免错误接管它们，不宣称修复所有自由文本幻觉。模型最终回答不是授权来源。

净收益门槛：主14段事实不退化、完成14/14、有害覆盖0，保留原两单颜色纠错；
异常安全12/12、业务不变、关时payload不变。逐段报告无关订单、同轮两次输入变化、
下轮字符和调用数；主矩阵两轮输入总开销不得比固定4b9c3cb更大。不能仅凭更短采纳。
所有脚本固定假模型、禁止外网、保留失败，字符不换算真实 Token。

先用真实代码完成原失败测试与 A 对照，再实施 B；若净收益不达标则不保留 B。
此文档在生产修改前生成；后续结果另存，既有冻结结果均不改写。
