# 意图路由 held-out 评测：真实模型分类基线

2026-10-30。与规则评测使用同一批 **170 条** held-out query（来自已有冻结任务），预期
标签按 gold tool 的必需工具族推导。模型为 `deepseek-flash`，temperature 0，非思考，
每条 query 一次分类请求，要求只输出 `{"routes": [...]}`。

这是**意图分类基线**，不是产品 V3 工具执行路径；没有评价回答质量和工具选择。

## 结果

| 指标 | 规则路由器 | 真实模型 |
|---|---:|---:|
| exact match | 37/170 = 21.8% | 51/170 = **30.0%** |
| coverage（expected ⊆ predicted） | 106/170 = 62.4% | 140/170 = **82.4%** |
| 缺失标签 | 70 | **31** |
| 多余标签 | 163 | **107** |
| 多意图 exact | 4/27 = 14.8% | 11/27 = **40.7%** |
| 多意图 coverage | 13/27 = 48.1% | 22/27 = **81.5%** |

调用与费用：

- 170 次模型请求；
- prompt 18,310 / completion 1,528 tokens；
- 126.3 秒；
- 估算 **0.052759 元**（按实际 usage 记录，最终以账单为准）。

## 解释

- 模型明显优于规则：coverage 82.4%，漏标签从 70 降到 31；多意图 coverage 81.5%。
- 但 exact 仍只有 30%，多余标签 107 个。模型倾向把“订单/退货/价格”等隐含语义都列上：
  - “我要退订单…先存草稿” → `orders+return`，Gold 只要求 return；
  - “现价和降噪” → `price+product`，Gold 只要求 product。
- 这说明 **Gold 只表示必需工具族，不表示穷尽语义意图**；exact 会低估模型，coverage 才是
  “有没有漏必需工具”的主指标。要评价“意图识别准不准”，还需要人工语义标签，不能只靠
  gold tool 反推。
- 31 个 missing 表明即使模型也不适合直接做硬 tool 白名单；若用作硬路由，仍会挡工具。

## 结论

- 模型分类比规则路由更可靠，但仍需：
  1. 独立人工语义标签，区分“必需 route”和“可选 route”；
  2. 明确 prompt/route schema，减少过度标注；
  3. 用 coverage 作为硬路由门槛，exact/F1 作为质量指标；
  4. 低置信度/缺 route 时走澄清或保留全工具，不能硬过滤。
