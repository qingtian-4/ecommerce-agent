## 主要发现、红绿与最小修改

| 问题 | 证据 | 处理 |
| --- | --- | --- |
| 诊断投影/中间保存/终态投影抛错中断核心轮次 | boundaries_red.log三个反例 | 仅可选诊断best-effort、故障锁存一次、记录阶段及异常类型；不吞核心finish_turn失败 |
| 已有草稿的本轮字段更正无法判断是否落库 | boundaries_red.log两反例：写前失败/commit后丢回执 | 核对请求字段、revision及本轮sources.turn_id，区分applied/not_applied/uncertain，展示实际当前值 |
| 异常写后模型再调用写工具可重复增加revision | uncertain_replay_red.log | Loop在不确定写回执后停止后续模型/同批工具；ChatService只核对、不重放 |
| 返回前组装政策失败可能已修改草稿 | review_boundaries_red.log | 先解析政策，再执行原事务写入，规则校验失败无写入 |
| 成功写后读状态失败逃逸 | review_boundaries_red.log | 形成state_uncertain终态；不再调用模型，不宣称成功 |
| 同批尚未执行工具导致工具消息不配对 | readback_batch_red.log 1failed/1passed | 为未执行调用补明确executed=false回执，真实核心状态仍不确定 |
| 恢复关闭时启动仍执行权威核对 | review_boundaries_red.log | 工作台显式绑定runtime_recovery_enabled；原running→interrupted清理保留 |
| 未核对的中断进度写“已核对” | review_boundaries_red.log | 文案与是否实际核对绑定，不靠模型原答生成进度 |
| 混合“订单+商品参数”漏售前工具 | routes_bound_red.log | 有限售前词增加“参数”，不扩大为通用语言分类器 |

关键测试是实际SQLite和脚本LLM，不需要密钥或网络。写异常前后均只执行一次，
旧字段失败时保留，成功时有本轮来源与revision；不将“草稿已存在”当本轮更正成功。
不将已保存草稿等同申请、审核或退款。

诊断错误不含完整异常文本或用户数据；真实终态仍由finish_turn一次落库。
诊断写失败不会触发重做业务，也不会停止读/写工具执行；核心数据库写/finish失败仍显式失败。
未见写入提交、权限、确认、幂等或审核规则放宽。

## 新冻结真实模型试验

10个新多轮/混合任务，8个自然任务和2个受控503任务；各臂一次，按任务交替顺序。
同一修复后代码，Baseline关闭Router/Recovery，Candidate开启两者。
P0/P1/颜色/聚合均开且相同，进度在两臂均关闭，以隔离路由与恢复贡献；
模型、温度、输出512、上下文、工具预算、政策和合成DB相同，每轮从SQLite恢复。
Prompt不为某臂增加词句。不给付费裁判，不重试挑选成功，不跑第二轮补分。
受控故障发生在发请求之前，不冒充供应商故障；真实任务与故障任务分别报告。

案例与词法/字段/历史同步判据先冻结在live_cases.json；原sha保留于各preflight manifest。
原始工具事实由场景DB推导，最终必须逐项人工源事实复核，词法判据不能当独立语义裁判。
无网络预演为20段、0付费请求，基线8/10、候选10/10只证明脚本与故障注入符合预期，
不代表真实模型收益。来源严格哈希锁定；live执行必须匹配最终预演。
